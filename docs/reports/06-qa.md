### What is not automated (honestly)
- **Wallet rejection / insufficient balance / account switch mid-flow**: NEAR wallets are third-party pages; there is no injected provider like Anvil+viem for EVM. The rejection path is handled in code (`callGasless` does not retry a rejection) and tested manually through `wallet-qa.mjs` with a real Intear wallet.
- **Local node/fork**: there is no Anvil equivalent for NEAR+MPC+light client; the tests run against the public testnet (not a simulation).
- **Page Object Model**: not used; the specs are short and use role/text-based locators. Adding a POM layer for 50 tests would not reduce duplication meaningfully.
