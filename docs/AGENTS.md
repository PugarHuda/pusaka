# Pusaka over MCP: every tool

Moved out of the [README](../README.md#for-ai-agents-pusaka-over-mcp); every transaction cited here is checked by `node scripts/verify.mjs`.

Tools: `pusaka_overview`, `pusaka_inspect` (verified BTC, USD value, ETH safe/at-risk, listing premium, loan LTV/APR, sign epoch), `pusaka_buy`, `pusaka_fund_loan`, `pusaka_repay_loan`, `pusaka_claim_collateral`, `pusaka_list`, `pusaka_cancel_listing`, `pusaka_request_loan`, the loan market (`pusaka_loan_offers`, `pusaka_offer_loan` with a max-LTV guard, `pusaka_cancel_loan_offer`, `pusaka_accept_loan_offer`, which also refinances a funded loan with a capped top-up, `pusaka_repay_partial`, `pusaka_propose_extension`, `pusaka_accept_extension`), gift links (`pusaka_gift_link`, `pusaka_claim_gift` signed with the link's own key, `pusaka_cancel_gift`; live: `node mcp/gift-agents.mjs pusaka-buyer.testnet pusaka-seller.testnet 2`), `pusaka_prove_deposits`, `pusaka_withdraw_btc`, `pusaka_withdraw_eth` (ETH or USDC on any of its EVM chains), `pusaka_withdraw_sol`, `pusaka_withdraw_near` (its own NEAR account), `pusaka_withdraw_nbtc`, `pusaka_stake_near` (stake, unstake or withdraw at a factory validator), `pusaka_swap_to_usdc` and `pusaka_swap_status` (sell the Pusaka's BTC for USDC on NEAR through NEAR Intents, executed; testnet via Tidepool), Pusaka v2 (`PUSAKA_CONTRACT=pusaka-v2.testnet`): `pusaka_token_account` (the NFT's own account, alias and post-quantum lock), `pusaka_account_send` (NEAR out of the NFT's account), `pusaka_set_agent` / `pusaka_agent_send` (an agent's daily budget from the NFT's account, enforced by the contract; live: `node mcp/v2-budget-agent.mjs`) and `pusaka_pq_unlock` (signs the ML-DSA-65 unlock with a key from the server's environment, never the conversation; live: `node mcp/v2-agent.mjs`, the agent's send was refused until its on-chain unlock, then [7VLy5ew6…](https://testnet.near.rocks/tx/7VLy5ew65YEtB3d2aUbXuwm3Aw6YdD82QTxbGPBjAxyN)), `pusaka_sign_in` (signs in to a website as the NFT, only for domains in `PUSAKA_SIGN_IN_DOMAINS` and with the person's yes), `pusaka_give`, `pusaka_mint`, `pusaka_set_heir`, `pusaka_still_here`, `pusaka_claim_inheritance`, `pusaka_set_guardians`, `pusaka_approve_release`. An agent can move everything a Pusaka holds. **Due diligence an agent can run before trusting it with money** (read-only, also on the remote server): `pusaka_contract_trust` (deployed code sha256 and its reproducible-build source, every key on the contract account, the DAO council and threshold that can change the code, the timelock and any pending upgrade), `pusaka_audit` (an independent proof-of-reserves of one Pusaka: asks NEAR's MPC signer which key it derives for this token, recomputes the verified sats, and looks every counted deposit up on Bitcoin, including whether it is still unspent), `pusaka_history` (provenance: holders, sale prices, loans), `pusaka_credit_record` (a borrower's repaid / refinanced / defaulted loans across every Pusaka, from the contract's own history), `pusaka_loan_watch` (every funded loan with hours left, live LTV and this agent's next move), and `pusaka_gift_preview` (what a gift link holds, without claiming it). `pusaka_paid_audit` buys the same audit per call over x402 on NEAR (0.001 wNEAR, under the spend cap, pinned to the checked price and payee; live [A2qiMjNA…](https://testnet.near.rocks/tx/A2qiMjNAiDhqe7weTJh4eKR6uxLXK22qTzAbJvCTCDTR)). **Market and portfolio:** `pusaka_deals` scans every listing against a live, solver-signed NEAR Intents quote for selling the BTC inside, so an agent can buy Bitcoin below its exit value (on testnet every listing priced 75% under, since testnet BTC is valued at mainnet prices); `pusaka_portfolio` sums what an account holds, owes, lent, escrowed and stands to inherit. **A letter only the holder can read, written by an agent:** `pusaka_write_letter` has the contract ask NEAR's MPC network for a confidential key (CKD) and seals the text into the NFT; `pusaka_read_letter` gets the same key for the current holder only and opens it, all inside the agent's process (live: an agent sealed a letter into #2 [44aR6Y1g…](https://testnet.near.rocks/tx/44aR6Y1gpwN5fXnMCPUrbyNnSNqmiDkGcf6kTAM8oeHX) and read it back). **Not only tools:** the server also speaks MCP resources (`pusaka://contract`, `pusaka://token/{id}` for every Pusaka) and prompts (`due_diligence`, `lender_round`, `buy_btc_below_exit`), ready-made routines an MCP host can offer its user. 55 tools in all. **The person stays in charge (MCP elicitation):** when the host supports it, every NEAR spend and every outflow is put to the person first ("The agent wants to offer loan, spending 0.02 NEAR…") and nothing is signed without their yes, so a sealed letter or a listing an agent reads can't spend for them (letters come back marked `untrusted_letter`); `PUSAKA_CONFIRM=off` runs autonomous under the caps. Live: `node mcp/elicit-qa.mjs`: declined, nothing signed and the spend cap restored; approved, the offer posted and was cancelled. Every tool carries MCP annotations (`readOnlyHint` for the 14 read tools, `destructiveHint` for the 17 that can move a Pusaka or its assets away: sold, pledged, given, inherited or withdrawn) so hosts can auto-allow reads and warn before outflows. The web app's [For AI agents](https://pusaka-two.vercel.app/#/agents) page lists the endpoint's tools, prompts and resources live and asks it `pusaka_contract_trust` on load. Live: `node mcp/due-diligence.mjs 1`; a lender agent funded #13 and both agents' `pusaka_loan_watch` showed 72 h left, LTV 0.25 and each one's next move, then the borrower repaid and `pusaka_credit_record` read 9 loans, 7 repaid, 2 refinanced, 0 defaulted. **Verified live through an MCP client (4 Nov):** [ETH on Sepolia](https://sepolia.etherscan.io/tx/0xd514c72366e9aa13de1223433544563848e00f020e2b1bef0e98388b35c4e9ed), [SOL on devnet](https://explorer.solana.com/tx/4oNMntvxmefB9L2jEdcmR3UNZC8xq2y2R4zFs18rbk5GhutjKCigezYfL6oLwFS27WnH6V1Uji3CuQi7Dp7ffuqE?cluster=devnet), [NEAR from #5's own account](https://testnet.near.rocks/tx/3YxDKPdAdp9Uy3J4dCojGechY1sXygXHCawwQtTEyk1D), and `pusaka_give` moved #7; it refused a nonexistent receiver, a malformed EVM address and more SOL than the Pusaka holds.
